可以，而且我建议你这次 migration 先通过 ESLint 配置兼容旧代码，不要为了过 Jenkins 一口气改几十上百个 any。

你现在主要报的是：

@typescript-eslint/no-explicit-any
@typescript-eslint/no-empty-object-type
@typescript-eslint/ban-ts-comment
react/display-name
unused eslint-disable directive

这些大部分都不是 Next 15 / React 19 运行必须修的。

如果你现在是 eslint.config.mjs，可以先类似这样：

import { defineConfig } from 'eslint/config';

export default defineConfig([
  {
    rules: {
      '@typescript-eslint/no-explicit-any': 'off',
      '@typescript-eslint/no-empty-object-type': 'off',
      '@typescript-eslint/ban-ts-comment': 'warn',
      'react/display-name': 'warn',
    },
  },
]);

如果你不想完全关掉，也可以先全部降成 warning：

rules: {
  '@typescript-eslint/no-explicit-any': 'warn',
  '@typescript-eslint/no-empty-object-type': 'warn',
  '@typescript-eslint/ban-ts-comment': 'warn',
  'react/display-name': 'warn',
}

这样：

以前：
Error → Jenkins fail

改后：
Warning → Jenkins 可以继续

我更推荐第二种思路：migration 阶段先 warning，不要马上 off 全部规则。

不过你截图里还有：

Unused eslint-disable directive

这个有时不是普通 rule，而是 ESLint 对没用的 eslint-disable comment 报告。

可以在 flat config 里考虑：

export default [
  {
    linterOptions: {
      reportUnusedDisableDirectives: 'warn',
    },
  },
];

这样旧代码里的：

// eslint-disable-next-line ...

即使现在已经不需要，也不会直接把 Jenkins 打红。

所以对你这个项目，我建议迁移期配置大概是：

export default [
  {
    linterOptions: {
      reportUnusedDisableDirectives: 'warn',
    },

    rules: {
      '@typescript-eslint/no-explicit-any': 'warn',
      '@typescript-eslint/no-empty-object-type': 'warn',
      '@typescript-eslint/ban-ts-comment': 'warn',
      'react/display-name': 'warn',
    },
  },
];

但有一个关键点：

不要直接拿这段覆盖。

因为你现在应该是从 cmt-oms-ui-equities-order-entry / cmt-ui-nextjs-template 拿了完整的 Next ESLint config。应该在现有 config 最后加一个 compatibility override，保留 Next 的其他规则。

比如概念上：

export default [
  ...existingNextConfig,

  {
    // Project B migration compatibility
    rules: {
      '@typescript-eslint/no-explicit-any': 'warn',
      '@typescript-eslint/no-empty-object-type': 'warn',
      '@typescript-eslint/ban-ts-comment': 'warn',
      'react/display-name': 'warn',
    },
  },
];

这样最符合你现在的目标：

先迁成功
↓
build/test/deploy 正常
↓
react-scripts 删除
↓
security scan 正常

以后再单独清理：
any
empty object type
old eslint-disable

不要把 CRA → Next migration 和 全项目 ESLint cleanup 绑在一个 change 里。

还有一点：如果 Jenkins 的命令是类似：

next lint

或者：

eslint . --max-warnings=0

那即使变成 warning，--max-warnings=0 仍然会失败。所以也要一起看 Jenkins/package.json 的 lint command。

如果是：

"lint": "eslint . --max-warnings=0"

migration 阶段可以改成：

"lint": "eslint ."

否则你把 error 降成 warning，Jenkins 还是红。

你现在这个问题，完全可以通过配置让它先正常跑，不需要先把所有 test/source code 改掉。
